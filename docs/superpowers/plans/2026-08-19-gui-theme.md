# GUI Theme (System Dark/Light Mode) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `mlai-gui` follows the OS light/dark preference by default, with no in-app toggle, but an adopter can pin `manifest.toml`'s new `[gui] theme` field to `"light"` or `"dark"` to override it.

**Architecture:** Add a `GuiConfig`/`Theme` type to `mlai-core::manifest::Manifest` (`#[serde(default)]`, so every existing manifest is unaffected). `mlai-gui`'s frontend already receives the full parsed `Manifest` via the existing `list_components` Tauri command — extend its TypeScript type and, on load, set `document.documentElement.dataset.theme` only when the manifest requests an explicit override. `styles.css` gets real CSS custom-property tokens: a light default, a `prefers-color-scheme: dark` media-query override guarded against an explicit light override, and an explicit dark override that wins regardless of system preference.

**Tech Stack:** Rust (`mlai-core`, existing `serde`), TypeScript/CSS (`mlai-gui`'s existing `main.ts`/`styles.css`, no new dependencies).

## Global Constraints

- Every step's exit criteria: `cargo build --workspace`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check` must all pass before commit (per `CLAUDE.md`).
- Every existing manifest (no `[gui]` table) must parse identically to before this change — `theme` defaults to `"system"`.
- No end-user-facing toggle in the GUI — explicitly ruled out.
- Design reference: `docs/superpowers/specs/2026-08-19-gui-theme-design.md`.
- Grounding note: verified directly against the current contents of `crates/mlai-core/src/manifest.rs`, `crates/mlai-gui/src/main.ts`, `crates/mlai-gui/src/styles.css`, `crates/mlai-gui/index.html`, and `crates/mlai-core/src/pipeline.rs`/`crates/mlai-gui/src-tauri/src/lib.rs` (both construct `Manifest { ... }` struct literals directly in their test fixtures — 15 call sites total between the two files as of 2026-08-19, found via `grep -rn "Manifest {" --include="*.rs" crates/`) on 2026-08-19.

### Task 2: Frontend theme application + CSS

**Files:**
- Modify: `crates/mlai-gui/src/main.ts`
- Modify: `crates/mlai-gui/src/styles.css`

**Interfaces:**
- Consumes: `Manifest.gui.theme` (Task 1 — arrives in the frontend as the JSON field `gui: { theme: "system" | "light" | "dark" }`, since `Theme` serializes via `#[serde(rename_all = "snake_case")]` and the existing `Manifest`/`Component` types already round-trip through Tauri's JSON IPC layer with matching casing, per every other field in this interface).
- Produces: nothing new for other tasks — this is the plan's final task.

- [ ] **Step 1: Extend the `Manifest` TypeScript interface**

In `crates/mlai-gui/src/main.ts`, change:

```typescript
interface Manifest {
  manifest_version: string;
  components: Component[];
}
```

to:

```typescript
interface Manifest {
  manifest_version: string;
  components: Component[];
  gui: {
    theme: "system" | "light" | "dark";
  };
}
```

- [ ] **Step 2: Apply the theme override on load**

In `crates/mlai-gui/src/main.ts`'s `loadComponents()` function, change:

```typescript
async function loadComponents() {
  try {
    const manifest = await invoke<Manifest>("list_components");
    renderComponents(manifest);
    await refreshModelOptions();
  } catch (e) {
```

to:

```typescript
async function loadComponents() {
  try {
    const manifest = await invoke<Manifest>("list_components");
    if (manifest.gui.theme !== "system") {
      document.documentElement.dataset.theme = manifest.gui.theme;
    }
    renderComponents(manifest);
    await refreshModelOptions();
  } catch (e) {
```

(leave the `catch` block and the rest of the function unchanged; a manifest that fails to load simply leaves the page following the OS preference via CSS alone, the same as `theme: "system"` would).
